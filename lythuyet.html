Trả lời 4 câu lý thuyết

Khái niệm, điểm khác biệt, ví dụ mã nguồn, ứng dụng và lưu ý bảo mật theo yêu cầu của đề.

Câu 1 (10 điểm) · position: relative và absolute

Relative: Phần tử vẫn giữ chỗ trong luồng bố cục bình thường; các thuộc tính top/right/bottom/left dịch chuyển nó so với vị trí ban đầu. Nó cũng có thể làm mốc định vị cho phần tử con.

Absolute: Phần tử ra khỏi luồng bố cục; vị trí được tính dựa trên khối chứa, thường là tổ tiên gần nhất có position khác static. Không có tổ tiên phù hợp thì khối chứa ban đầu được dùng.

RelativeAbsolute
Giữ khoảng trống ban đầu trong bố cụcKhông giữ chỗ trong luồng bình thường
Thích hợp chỉnh lệch nhẹ, làm mốc cho conThích hợp nhãn giá, biểu tượng đè lên ảnh
.khung { position: relative; width: 80%; max-width: 500px; }
.nhan { position: absolute; top: 8px; right: 8px; }
@media (max-width: 600px) { .khung { width: 100%; } }

Responsive: Không nên dựa vào tọa độ cố định cho cả trang vì dễ tràn và chồng lấn trên mobile. Kết hợp phần trăm, max-width, media queries và bố cục linh hoạt. Sau khi deploy, CSS vẫn chạy như lúc phát triển nhưng phải kiểm tra nhiều kích cỡ màn hình bằng DevTools.

Câu 2 (10 điểm) · Domain, Hosting, DNS và deploy

Quy trình: (1) Chọn và đăng ký tên miền; (2) chuẩn bị hosting hoặc nền tảng tĩnh; (3) tải bộ file HTML/CSS/JS lên dịch vụ; (4) cấu hình các bản ghi DNS do nhà cung cấp hướng dẫn; (5) bật HTTPS/SSL; (6) kiểm tra tên miền, link và giao diện.

DNS: Hệ thống phân giải tên miền thành thông tin định tuyến. Bản ghi A trỏ đến IPv4; CNAME là bí danh trỏ đến tên miền khác. Việc thay đổi DNS có thể cần thời gian để cập nhật ở các bộ nhớ đệm.

Giải pháp không tự quản trị server: GitHub Pages và Netlify đều cho phép triển khai website tĩnh HTML, CSS, JavaScript. Có thể nối repository Git để cập nhật tự động (tùy nền tảng và thiết lập). Không nên coi hosting tĩnh là backend có cơ sở dữ liệu.

Rủi ro: Thiếu HTTPS làm giảm bảo mật đường truyền; lộ khóa API hoặc mật khẩu trong JavaScript; sai quyền truy cập và lỗi XSS. Cách phòng tránh gồm bật HTTPS, không nhúng bí mật vào frontend, kiểm soát dữ liệu đầu vào và bảo vệ tài khoản quản trị.

Câu 3 (10 điểm) · var, let, const; Scope và Hoisting

TDZ (Temporal Dead Zone) là khoảng thời gian không được truy cập biến trước khi dòng khởi tạo được thực thi. Với const, không thể gán lại biến, nhưng thuộc tính trong object vẫn có thể sửa nếu object không bị đóng băng.

console.log(a); // undefined
var a = 10;

// console.log(b); // ReferenceError vì TDZ
let b = 20;
const c = 30;

Lỗi thường gặp: Đọc let/const trước khởi tạo gây ReferenceError; sửa giá trị gán cho const gây TypeError. Để debug, mở Chrome DevTools bằng F12, xem tab Console, thêm breakpoint ở Sources và quan sát Scope/Watch hoặc sử dụng console.log().

Khuyến nghị: Ưu tiên const khi không cần gán lại; dùng let khi cần cập nhật; tránh var trong mã mới.

Câu 4 (10 điểm) · Event Delegation

Khái niệm: Đăng ký trình lắng nghe sự kiện ở phần tử cha để xử lý tương tác của nhiều phần tử con. Với sự kiện click, cơ chế event bubbling cho phép sự kiện nổi từ con lên cha.

Ví dụ: Một danh sách <ul id="list"> có nhiều <li>; mỗi li chứa nút <button class="xoa">Xóa</button>. Chỉ cần lắng nghe click ở ul.

const list = document.getElementById("list");
list.addEventListener("click", (event) => {
  const btn = event.target.closest("button.xoa");
  if (btn && list.contains(btn)) {
    btn.closest("li")?.remove();
  }
});

Ý nghĩa: Dùng closest() để nhận nút được nhấn và kiểm tra nó thuộc danh sách. Khi có sản phẩm được thêm bằng JavaScript, sự kiện vẫn hoạt động mà không cần đăng ký listener mới.

Lợi ích: Giảm lượng listener, dễ bảo trì và hoạt động với danh sách động. HTML tạo cấu trúc, CSS định dạng, JavaScript xử lý các sự kiện; cần chú ý loại sự kiện có bubbling và không xử lý nhầm phần tử ngoài vùng cần quản lý.
